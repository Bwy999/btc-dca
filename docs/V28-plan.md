# Sats Garden V28 重构计划

目标：**少而准**。从约 40 个模块减到 21 个核心模块；数据由 GitHub 预先算好，手机只读文件；样式和图表各用一套公用组件。
做法：新旧并行——V28 在单独的预览地址开发，V27 照常使用；个人记录（账本、计划、设置）沿用原来的存储键，不用重新录入。

## 一、模块清单（2026-11-11 与用户确认）

**保留（21）**
首页：价格 + AHR999、今日结论（含依据）、AHR999 走势
分析：顶底区间（含深度底部、底部确认）、周期时钟、稳定币流动性
链上：持币成本分位带、各币龄的持币成本、LTH_PSIL、LTH 筹码集中度、长期持有者每月持仓变化、长 / 短期持仓比率、长期持有者分组成本、持币地址分布
定投：本月应投卡片、定投策略对比
我的：本月预算（并入定投页）、持仓 + 个人成本曲线、买入记录（含备份）、21M 长期积累、数据健康中心（简化）

**收进资料库（21）**
价格关键位、指标明细（五类分项）、回撤、周期阶段、均线结构、幂律走廊、恐惧贪婪、资金费率、成本基础价格、STH / LTH 资本化价格、
筹码分布、花费脉冲、币龄销毁、LTH NUPL、老币重新流通、持币群体净变动、算力与难度、矿工收入、量子准备度、六条铁律、自托管操作窗口

**删除（7）**
周期底部探索、周期顶部探索（已并入顶底区间）、市场结构图谱、实时共识 Floor、预测市场、深度亏损供应、回撤触发（信号定投之前的老规则）

说明：收起 / 删除的只是「不再显示」；数据如果被定投规则用到（如顶底区间的「老币行为」分项），后台照样计算。

## 二、分区（5 → 4）
首页（价格、今日结论、本月应投）· 定投（计划、记录、回测）· 指标（核心模块 + 资料库入口）· 我的

## 三、数据层（第二步，已开始）
`tools/v28_build_data.py`（工作流 `v28-data.yml`，每 6 小时）写两个文件：

| 文件 | 内容 | 大小 |
|---|---|---|
| `data/v28/core.json` | `latest`：价格、LTH_PSIL、长期持有者 30 天变化、长短期比率及距高点、成本中位 / 25 / 75 分位、现价分位、分组成本四条线最新值、近 1 个月买入者；`percentiles`：19 个成本分位；`sync`：Bitview 同步状态 | 几 KB |
| `data/v28/charts.json` | `daily`（近 1,100 天：价格、PSIL、长 / 短期持币量、30 天变化、成本分位带）；`priceAll`（全部日收盘，AHR999 用）；`cohortWeekly`（分组成本四条线，周度）；`age`（六组币龄的持币量、平均成本、盈利占比 + 成本分布） | 约 200 KB |

规则：每组数据一个函数、互不影响；某一组读取失败就沿用上一次文件里的那一组并记入 `stale`。
沿用现有文件：`data/monthly.json`（顶底区间）、`data/lth-chips.json`、`data/stablecoins.json`、`data/daily-state.json`、`data/quantum.json`。
待补（做指标页时加）：持币地址分布、稳定币 12 小时（仍由手机实时取 CoinGecko）、AHR999 在脚本里直接算好。

## 四、步骤
1. ✅ 确定模块清单
2. ✅ 数据层（GitHub 预计算）——`tools/v28_build_data.py` + `v28-data.yml`；预览 3 起多了 `monthly`（按月价格与 LTH_PSIL）、`addr`（持币地址分布）、`ahrAll`（AHR999 全部历史）三组
3. ✅ 首页 + 定投页（预览 2）
4. ✅ 指标页（12 个核心指标，一个公用图表组件）+「我的」（持仓、成本曲线、21M、预算 / 汇率设置、数据状态、备份）+ 资料库入口（预览 3）
5. ⏳ 切换上线：先在 `/v28/` 用真实数据看一段时间，确认无误后把 V28 换成首页，V27 挪到 `/v27/` 保留可退回

定投日推送：`tools/daily_state.py` 每月 15 日（北京时间）推送「本月应投」；预算、日期可用仓库 Variables `DCA_BUDGET` / `DCA_DAY` 调整。
18 日「未记录」提醒不做——买入记录只存在手机上，GitHub 看不到，做了只会误报。
