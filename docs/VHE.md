# SatsGarden V28.2.0 · VHE 波动增币实验室技术说明

> 本文档说明「波动增币实验室（Volatility Harvesting / BTC-Accumulating Lab，简称 VHE）」的数据规范、数学公式、子仓状态机、现金与持币对账守恒及方法局限。本模块仅为本机历史模拟实验室，不构成任何交易建议，也不连接任何实盘账户。

---

## 1. 设计目标与隔离边界

1. **币本位评价核心**：在完全相同的起始资产与完全相同的外部现金流（入金日期与金额）下，比较期末**实际持仓 BTC（`heldBTC`）**、**未回购/未投现金（`cashUSD`）**与**BTC 等价总资产（`eqBTC`）**。绝不用美元账面涨幅掩盖币量损耗。
2. **现金与持币严格分列**：待回购现金与外部留存现金始终独立展示，绝不直接混入「实际持仓 BTC」数字。
3. **本机真实账本零写入**：
   - VHE 实验参数仅保存在独立本地键 `btc_vhe_config_v1`。
   - 第一阶段严禁修改或写入用户的真实定投账本（`btc_dca_ledger_v1`）与主站执行记录（`btc_exec_v7`）。
   - 页面提供可选的「只读带入本机持仓」按钮，仅单向读取现货 BTC 数量作为模拟起点；默认 `0.30 BTC` 明确标注为示例模拟仓位。
4. **纯静态与按需加载**：独立页面 `vhe.html` 引用带 10 位 SHA-256 内容哈希的 `assets/vhe.<hash>.css`、`assets/vhe-engine.<hash>.js`、`assets/vhe-ui.<hash>.js`，纳入 Service Worker 的 `OPTIONAL_ASSETS`（不增加首页冷启动负担，首次访问后支持离线打开）。

## 2. 数据规范与时间口径

1. **同源优先与连续性证明**：
   - 首选同源预生成 `./data/v28/charts.json` 的 `priceAll`。
   - `tools/v28_build_data.py:g_price_all()` 升级为 `schema: 2`：保留旧字段 `start` 与 `v` 兼容，同时输出完整 UTC 日历网格的显式日期数组 `d`、`end`、`gaps` 与 `contiguous` 标志。
   - 若遇到仅含 `start/v` 而无显式日期数组 `d` 的旧版 `priceAll`，引擎将其标记为 `verified: false` 并拒绝进入正式回测，自动独立切换至随包验证种子 `CYCLE_SEED`，**绝不静默混合两个数据源**。
2. **缺日、乱序与未完成日处理**：
   - 严格拒绝重复日期（`DUPLICATE_DATE`）与乱序日期（`OUT_OF_ORDER_DATE`）。
   - 自动排除当前未完成 UTC 日（`date >= asOfUtcDay`）。
   - 若原始序列存在缺日或非正数/`NaN` 价格，在完整 UTC 日历网格原位保留 `close: null` 并记录于 `gaps`，**绝不将后续日期前移顶替**。默认回测窗口策略（`gapPolicy: "reject_window"`）在预热或回测区间遇到缺口时直接拒绝该窗口；可选 `pause_signals` 在缺口后清零连续日计数并暂停信号，直至重新满 `MA` 预热长度。
3. **价格语义与新鲜度**：
   - Bitview `day1` 序列未绑定单一交易所撮合收盘时刻，界面统一标明为**日参考价**而非交易所收盘价。
   - 严禁用 `charts.json` 的文件生成时间戳 `ts` 冒充数据日；末数据日距离当前 UTC 日超过 3 天（或使用 `CYCLE_SEED`）一律标记 `滞后 · MM-DD`。
4. **禁止误用快照数据**：
   - V28.1.1 新增的 `charts.urpd.prev`（1日/7日/30日筹码变动对比）属于离散快照而非带 `availableAt` 的逐日历史归档，VHE 严禁使用当前 URPD 快照生成历史回测信号。

## 3. 均线特征、成交模型与费用公式

### 3.1 算术 MA200 与 AHR999 成本区分
- **算术均线 `MA(N)`（默认 `N = 200`）**：取截至当日 `t`（含）连续 `N` 个已完成有效日参考价的算术平均值：
  $$\text{MA}_t = \frac{1}{N}\sum_{k=t-N+1}^{t} P_k, \quad \text{偏离率 } \text{dev}_t = \frac{P_t}{\text{MA}_t} - 1$$
  每个回测起点前强制保留至少 `N` 个完整有效日预热，确保起点前一日 `t-1` 与起点当日 `t` 均具备有效 `MA` 以判定向上穿越。
- **AHR999 200 日定投成本**：为近 200 日价格的**调和均值** $\text{HM}_{200,t} = 200 / \sum (1/P_k)$，与算术 `MA200` 严格区分。若启用第二批 `AHR999 动态定投` 对照，页面显式提示 `2026` 新拟合系数（`A = 5.5856, B = −16.1567`）在早期历史重放中存在模型选择后见风险。

### 3.2 Close-Only 次日执行（零未来数据泄漏）
由于不存在全历史逐笔或日内高低价文件，所有规则严格遵循 **`T` 日收盘后确认信号 → `T+1` 日参考价模拟市价执行**：
- 任意成交记录恒满足 `executionDay > signalDay`。
- 严禁在同一根日线先看收盘价再按当日价格成交，严禁假设盘中触价成交或挂单必成。
- 回测末日（`T = endDay`）触发的信号仅记录在 `pendingSignals` 中，不计入已成交明细，绝不偷看 `endDay + 1`。

### 3.3 报价币费用与单边滑点公式
设单边手续费率为 $f$（默认 `0.10%`），单边滑点率为 $s$（默认 `0.05%`），执行日参考价为 $P_{t+1}$（此处统一采用报价币 USD 扣费假设）：
- **卖出净到账美元**：
  $$\text{ExecPrice}_{\text{sell}} = P_{t+1}\cdot(1 - s), \quad \text{CashNet}_{\text{USD}} = Q_{\text{BTC}} \cdot P_{t+1} \cdot (1 - s) \cdot (1 - f)$$
- **买入实收 BTC**：
  $$\text{ExecPrice}_{\text{buy}} = P_{t+1}\cdot(1 + s), \quad Q_{\text{BTC}} = \frac{\text{Spend}_{\text{USD}} \cdot (1 - f)}{P_{t+1} \cdot (1 + s)}$$

## 4. 仓位结构与子仓状态机

- **核心仓与实验仓隔离**：起始仓位按 `1 - tradeRatio`（默认 `90%`）划入**核心仓（`coreBTC`）**，按 `tradeRatio`（范围 `0%–10%`，默认 `10%`）划为实验仓并均分为 `A / B / C` 三个独立子仓（各占实验仓 `1/3`）。
- **状态流转**：`HOLDING（持币） → PENDING_SELL（T日信号待卖） → WAITING_BUYBACK（等待回购） → PARTIAL_BUYBACK（部分回购） → HOLDING（回合完成）`。
- **防重复与穿越约束**：
  1. 卖出仅在 `prevDev < thr` 且 `curDev >= thr`（默认 `+25% / +40% / +55%`）向上穿越当日触发一次；连续多日位于阈值上方不会重复触发；子仓未完成整个回购或止损周期前绝不允许再次卖出。
  2. 回购锚点固定为该子仓**实际卖出成交价** $\text{Anchor} = \text{ExecPrice}_{\text{sell}}$。卖出所得净现金按 `1/3, 1/3, 1/3` 分配至 `−10% / −20% / −30%` 三档（第三档吸收浮点尾差使三档之和严格等于净现金），每档最多触发一次。
  3. **同日风险优先**：当任一待回购子仓触发风控退出（如较锚点上涨 `+20%` 止损回购，或等待满 `90` 天超时退出）时，立即取消该子仓剩余未成交的回撤档位，在 `T+1` 将该子仓剩余现金全额回购为 BTC，且**当日禁止其他子仓新增卖出信号**。
  4. **盈亏结算不伤核心仓**：回合结束时，若回购所得 BTC 大于本轮卖出 BTC（$\Delta \text{BTC} > 0$），净增部分转入 `coreBTC`，子仓恢复本轮卖出前币量；若净损币（$\Delta \text{BTC} < 0$），损耗完全由该子仓承担（子仓缩小），**核心仓绝不减少、绝不向子仓补仓**。

## 5. 评价指标与对账守恒方程

1. **等价资产与超额**：
   $$\text{eqBTC} = \text{heldBTC} + \frac{\text{cashUSD}}{P_{\text{mark}}}, \quad \Delta\text{eqBTC} = \text{eqBTC}_{\text{vhe}} - \text{eqBTC}_{\text{baseline}}$$
2. **币本位最大回撤**：
   - 无外部新增资金时：$\text{DD}_t = 1 - \text{eqBTC}_t / \max_{u \le t}\text{eqBTC}_u$。
   - 含外部定投入金时：按每次入金当日参考价折算的等价 BTC 申购份额，计算**现金流调整后的单位净值（Unitized NAV）**峰值回撤，避免持续入金掩盖真实回撤。
3. **卖飞损失（`soldOutLossBTC`）**：汇总全部已完成亏损回合的实损币量，以及期末仍未完成回购子仓相对「若未卖出一直持有」的未实现币量差额，不因部分获利回合掩盖踏空成本。
4. **净投入成本口径**：仅当起始仓位为 `0` 或用户显式填写已知起始净投入成本时，分别展示 `累计外部净投入 / 实际持仓 BTC` 与 `累计外部净投入 / eqBTC`（非税务成本）；起始本金未知时明确隐藏绝对成本。
5. **双守恒审计（每次运行自动校验，容差 `1e−10`）**：
   $$\left|\left(\text{BTC}_0 + \sum \text{BTC}_{\text{dca}} + \sum \text{BTC}_{\text{buyback}} - \sum \text{BTC}_{\text{sell}}\right) - \text{heldBTC}_{\text{end}}\right| \le 10^{-10}$$
   $$\left|\left(\text{Cash}_0 + \sum \text{Inflow}_{\text{ext}} + \sum \text{Cash}_{\text{sell,net}} - \sum \text{Spend}_{\text{dca}} - \sum \text{Spend}_{\text{buyback}}\right) - \text{Cash}_{\text{end}}\right| \le 10^{-10}$$

## 6. 实测基准结果与研究局限

基于随包真实历史种子 `CYCLE_SEED`（`2010-08-18` 至 `2026-09-26`，共 `5,884` 条完整 UTC 日收盘，单边费率 `0.10%`、滑点 `0.05%`、`10%` 波段仓、涨 `20%` 止损回购）：
- **5 个代表性固定起点**（`2017-12-01`、`2018-12-01`、`2021-11-01`、`2022-11-01`、`2024-01-01`）：相对纯 HODL 分别为 `−0.07%`、`−1.10%`、`−1.25%`、`−3.23%`、`−2.17%`（**0/5 跑赢**）。
- **跨起点滚动窗口**（`24 / 36 / 48` 个月，分别为 `163 / 151 / 139` 个重叠月度样本）：跑赢占比仅为 `27.61% / 25.17% / 20.86%`，中位超额分别为 `−1.48% / −1.92% / −2.22%`。
- **预注册分段检验**（`2013–2020` 训练期 → `2021–2026` 样本外）：训练期选出的非零候选（`5%` 波段上限）在样本外 `24` 个月滚动窗口中跑赢率仅 `24.44%`，中位超额 `−0.86%`，**未通过候选研究门槛，系统如实标记为「未证明增币能力」**。

因此，初始 `MA200` 偏离卖出方案在单边趋势牛市中容易过早卖出并触发止损损耗，不得作为推荐实盘策略；长期持有（HODL）与纪律定投仍是默认基准。
