BTC Intelligence 是一款面向长期比特币持有者与定投者的移动端信息终端。

首页聚焦两个核心：**比特币现在多少钱，以及 AHR999 处于什么位置。** 需要进一步判断时，再展开周期估值、链上成本、矿业数据与个人执行计划。

它不试图用单一指标预测价格，而是把长期结构、估值位置、网络基本面、市场流动性和个人计划放在同一套可核对的框架中。在市场最嘈杂的时候，仍然知道自己处于哪里、应该观察什么，以及如何保持既定纪律。

不自动交易，不鼓励杠杆，不承诺收益。

## Core Intelligence

### BTC Price & AHR999

AHR999 是这个项目的精神原点，也是首页的核心估值坐标。

| 能力 | 当前设计 |
|:---|:---|
| **价格优先** | BTC 当前价、24 小时与 30 日变化、近期走势 |
| **双模型** | 新拟合 / 经典切换，数值、曲线、色带与分区价格同步更新 |
| **历史范围** | 30日 / 90日 / 1年 / 全部可用历史 |
| **坐标选择** | 30日、90日采用线性坐标；1年、全部采用对数坐标 |
| **估值分区** | 深度低估、长期低估、估值偏热、高估风险四档淡色背景 |
| **交互读数** | 触摸、鼠标或方向键查看日期与收盘指数 |
| **来源区分** | 当前报价、手动试算、历史收盘分别表达 |

首次访问默认使用新拟合模型与 90 日范围；之后优先恢复已保存的浏览偏好。

历史指数基于已完成日线与连续 200 日成本计算。缺失日、无效价格不会被插值为完整历史，当前报价与手动试算不覆盖历史收盘。“全部”指当前实际可用的有效历史，并非承诺获取比特币诞生以来的所有样本。

新拟合历史边界按对应日期计算，右轴关键边界数字对应区间末日；不把经典固定阈值直接套到新拟合历史上。

独立的 [`ahr999.html`](./ahr999.html) 保留为 AHR999 致敬与模型研究入口。本次主页面更新不替换已有独立页面。

### Long-Term Power Law

BTC 历史价格与三条长期幂律模型线同屏展示：

- **支撑线** — 长期压力区参考
- **公允线** — 时间回归中枢
- **阻力线** — 历史周期顶部参考
- **区间位置** — 当前价格在支撑与阻力之间的位置
- **偏离度** — 现价相对公允价值的距离
- **领先支撑** — 当前价格相当于未来何时的模型支撑

模型展示公式如下，阻力线系数为便于阅读的近似值：

```text
公允价 = 10^-17.016  × d^5.845
支撑价 = 10^-17.466  × d^5.845
阻力价 ≈ 10^-13.3663 × d^5.0293
```

其中 `d` 为自 2009-01-03 创世区块以来的天数。模型延伸至 2035 年，实际历史覆盖以成功获取的数据为准。

### Dual Floor System

两种独立口径交叉观察长期压力区：

| 模型 | 方法 | 主要输出 |
|:---|:---|:---|
| **Bitview CM Floor** | 历史样本尾部分位 | `p95`、`p99`、`p99.5` 压力价格 |
| **UTXO Floor Band** | UTXO 加权中位成本与历史左尾分位 | 成本锚 `C50`、常见压力底 `5%`、极端压力底 `2%` |

底价是历史结构参考，不是不会跌破的价格保证。

### Regime & Cost Structure

- **Regime 引擎** — 汇总多指标状态，展示市场阶段、持续时间、主要驱动与阶段置信度。
- **成本基础价格** — 观察 STH Realized Price、True Market Mean 等链上成本参考。
- **成本结构状态机** — 将成本位置与预设执行规则放在一起，区分基础定投、额外档位与等待状态。
- **STH / LTH 与筹码分布** — 观察不同持币群体的资本化价格、持币变化和浮亏结构。

阶段置信度表示规则与数据支持程度，不等于未来涨跌概率。成本线用于解释市场结构，不代表绝对支撑或自动买卖指令。

### Mining Fundamentals

算力与难度使用两张独立图表，避免双轴造成误读：

- 支持 `3月 / 1年 / 3年 / 全部` 四档范围
- 算力采用周均面积线，观察矿工投入与网络算力变化
- 难度采用阶梯线，展示调整周期内的协议状态
- 长周期使用保形抽样，兼顾手机端可读性
- 全周期变化使用紧凑增长倍数，避免极大百分比失去可读性

### Valuation Engine

主终端保留七维估值：

`AHR999` · `价格 / 200WMA` · `MVRV` · `恐惧贪婪` · `Puell Multiple` · `Reserve Risk` · `SOPR`

评分根据数据新鲜度与可靠性动态校准。数据可用性与估值结论分别表达；缓存、滞后和缺失状态明确显示，不用过期数据制造确定性。

## Accumulation System

- **21M 长期积累** — BTC、sats、永久仓目标与 2100 万分之一占比
- **三池预算** — 基础定投、回撤加仓、极端预备金分离
- **回撤档位** — 触发、执行与等待状态独立记录
- **持仓与流水** — 跟踪投入、持仓成本与买入记录
- **本月进度** — 读取真实执行流水；冲突或待核对时显示对应状态
- **策略回测** — 比较普通定投、AHR999 经典、新拟合及连续加权策略
- **本地备份** — 通过 JSON 导入、导出个人数据

回测用于比较历史条件下的策略表现，不能当作实际账户收益或未来收益承诺。

## Data Integrity

数据读取、有效性校验、时间标注与缓存降级共同构成数据健康机制。数据健康中心用于核对来源、数据日期、拉取时间与失败状态。

| 数据域 | 代码配置的主要来源 | 失效处理 |
|:---|:---|:---|
| 现价与交易结构 | Binance、OKX、Coinbase、CoinGecko | 按现有逻辑使用备用源与有效缓存 |
| 长期价格与矿业 | mempool.space、Blockchain.com | 主备数据与本地缓存 |
| 链上与周期 | Bitview / BRK、Coin Metrics、BGeometrics、bitcoin-data.com | 标注缓存、滞后或缺失 |
| 情绪与流动性 | Alternative.me、DefiLlama | 使用可用数据并显示状态 |
| 统计与 UTXO 底价 | Bitview、`floor.json` | 本地快照与缓存降级 |
| 市场隐含概率 | Polymarket | 按现有规则过滤失效市场 |

上表描述代码中的数据接入，不代表每个来源均已通过本次实时联网验收。

部分缓存有效期按数据属性分层：

| 缓存 | 配置有效期 |
|:---|:---|
| 核心行情缓存 | 约 30 分钟 |
| 矿业历史、CM Floor 及部分 Bitview 模块 | 约 6 小时 |
| 幂律价格历史、UTXO 底价 | 约 24 小时 |

**缓存有效期不等于自动刷新间隔，也不等于底层数据日期。** 日频模块标注数据日；AHR999 标注成本日；数据健康中心区分完整 UTC 日期与拉取时间。

首页历史请求失败时保留已有曲线。数据不足时显示空状态，不生成模拟曲线填补；局部“重试历史”只恢复当前页面的图表数据，不新增持久行情缓存。

## Local-First Privacy

- 预算、持仓、买入记录与设置保存在当前浏览器，换设备或换站点地址不会自动同步
- 可选 BGeometrics API Key 保存在当前设备，不内嵌到交付 HTML，也不包含在现有 JSON 备份中

- 页面仍需向外部数据接口发送请求；本地保存个人记录不意味着网站完全离线运行

## Quick Start

主页面使用原生 HTML、CSS 与 JavaScript。**交付版可直接静态部署；可维护源码通过 Node.js 构建为单文件主页面。**

### 手机更新现有站点

1. 导出个人 JSON 备份，保留旧版 `index.html` 与 `sw.js`
2. 将 `01_index_V25_0_9_复制内容.txt` 全选复制，完整覆盖原站点的 `index.html`
3. 将 `02_sw_V25_0_9_复制内容.txt` 全选复制，完整覆盖同目录的 `sw.js`
4. 保留已有 `ahr999.html`、`dca.html`、`floor.json`、图标与其他资源
5. 等待原发布流程完成，在数据健康中心确认 V25.0.9

逐个上传时最后更新 `sw.js`。如果只更新本 README，不需要重新上传页面文件。

本次替换包用于更新现有网站，不包含从空仓库建立全站所需的全部独立页面与资源。

### 本地预览交付版

在包含生产文件 `index.html` 的目录运行：

```bash
python3 -m http.server 8080
```

浏览器打开 `http://localhost:8080`。接口访问是否成功仍受网络与数据服务状态影响。

### GitHub Pages / Existing VPS Workflow

继续使用原站点的发布目录与已配置的发布流程，将配套的 `index.html` 和 `sw.js` 一并更新。

若 VPS 已配置 GitHub 同步或 Floor 定时更新任务，可保留原流程。本次文件不会创建、修改或验证这些服务器任务，也不会自动发布到正式站点。

若 PWA 仍显示旧版，先关闭后重新打开，并检查发布是否完成。不要为了更新而清除本机账本。回退时将备份的 `index.html` 与 `sw.js` 一并恢复。
